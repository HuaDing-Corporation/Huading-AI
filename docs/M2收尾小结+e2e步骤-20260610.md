### 关键决策与发现
- **契约升级靠耦合落地**：#17 把 REST 契约升级为 `status: queued/running/done/failed` + `playback_url/download_url`；旧前端不兼容，故 #18 把前端迁到新契约，**两 PR 同批合**（单独合任一方都破 develop）。
- **后端契约内部不一致（已兜住）**：REST 用新契约，但 **SSE 仍发旧 worker 帧**（大写 `SUCCESS/PROGRESS`、progress 0..1、`video_url`）。前端做双映射：SSE 给实时进度，流结束/轮询用 `GET /videos/{id}` reconcile 取权威 `playback_url`，杜绝"完成→排队中"回退。
- **审查结论**：IDOR（跨租户 404）、Range/seek（206 + SigV4 + path-style + CORS）后端实测过；#18 代码级零必改。

## 二、全栈 e2e 步骤（部署 + 验证）

> Docker 由你本机跑（Agent 跑不了）。起来后，点击验证/截图可由 Claude Code 或我经 Chrome 代跑。
> 下面 env 以仓库 `infra/.env.example` 为准，这里列关键项。

### Phase 0 — 前置检查
1. **Docker Desktop 运行中**。
2. **端口空闲**：`3000`（前端）、`8080`（后端，因 8000 被 winnat 占）、`9000`/`9001`（MinIO API/控制台）、以及 compose 内部的 pg/redis。
   - 查占用：`netstat -ano | findstr :3000`（被 node 占 → `taskkill /PID <pid> /F`）。
3. **火山方舟（Ark）控制台已开通 Doubao-Seedance-2.0**——否则文生/图生会报 `ModelNotOpen`。
4. **DeepSeek API key 可用**（LLM 仍走 DeepSeek）。

### Phase 1 — 配置 `infra/.env`
关键项（占位值换成真实值）：
```env
# 鉴权
JWT_SECRET_KEY=<32+ 随机串>
# LLM（DeepSeek）
ENGINE_LLM_API_KEY=<DeepSeek key>
# Seedance 视频模型（注意前缀是 ENGINE_SEEDANCE_，不是 SEEDANCE_）
ENGINE_SEEDANCE_API_KEY=<Ark key>
ENGINE_SEEDANCE_MODEL=<Doubao-Seedance-2.0 的模型ID>
# 对象存储（MinIO）
ENGINE_S3_ENDPOINT=http://minio:9000           # 容器内部读写
ENGINE_S3_PUBLIC_ENDPOINT=http://localhost:9000 # 浏览器预签名主机（关键！别填 minio:9000）
ENGINE_S3_ACCESS_KEY=huading
ENGINE_S3_SECRET_KEY=<32+ 随机串>
ENGINE_S3_BUCKET=huading-videos
ENGINE_S3_REGION=us-east-1
ENGINE_S3_SECURE=false
ENGINE_S3_PRESIGN_TTL=3600
MINIO_ROOT_USER=huading
MINIO_ROOT_PASSWORD=<同 SECRET 或独立>
# 端口/前端
BACKEND_PORT=8080
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080
```

### Phase 2 — 起全栈 + 建账号
1. 起服务：
   ```bash
   docker compose -f infra/docker-compose.full.yml up --build
   ```
2. 等全部健康：`pg`、`redis`、`minio`、`backend`、`worker`、`frontend`。
3. （首次）**MinIO bucket**：若 compose 没自动建，进 `http://localhost:9001`（用 MINIO_ROOT_*）建 `huading-videos`，设私有；如下载跨域失败再给 bucket 配 CORS allow `http://localhost:3000`。
4. **注册首账号**：前端暂无注册页 → 打开 `http://localhost:8080/docs`（Swagger）调注册接口建租户账号。

### Phase 3 — 三模式 e2e（核心验证 + 截图）
打开 `http://localhost:3000` 登录，进工作台。对**每个模式**走一遍：

**① 静态模板**（pipeline standard）
- 输入主题 → 选「静态模板」→ 点生成。
- 看 SSE 进度条推进 → 状态变 **done**（不应回退到"排队中"）。
- 任务卡出现**内嵌播放器**：▶ 能播、**拖动进度条能 seek**、**下载**按钮能下 mp4。
- 📸 截图：播放器播放中 + 拖动后的画面。

**② Seedance 文生**（seedance_t2v）
- 输入主题 → 选「文生」→ 生成 → 同上验证播放/拖动/下载。
- 📸 截图。

**③ Seedance 图生**（seedance_i2v）
- 选「图生」→ **上传商品图**（jpeg/png/webp，<10MB）→ 生成 → 同上验证。
- 📸 截图。

**④ 列表持久化（hydrate）**
- **刷新页面（F5）** → 之前的任务/成片**仍在列表**，不丢历史。
- 📸 截图刷新后的列表。

**⑤ 移动端**
- DevTools 切窄屏（≤sm）→ 工作台无横向溢出、模式 pill 不重叠、返回键可见。
- 📸 截图窄屏。

### Phase 4 — DevTools 检查（Chrome DevTools / Network）
- **Console**：无红色报错。
- **Network**：
  - `GET /api/v1/videos`、`/videos/{id}` 返回里 `playback_url`/`download_url` 是 `http://localhost:9000/...` 的预签名 URL（**不是** `file://`、**不是** `minio:9000`）。
  - 播放时视频请求带 `Range`、返回 `206 Partial Content`。
- **onError 刷新**：等预签名 URL 过期（>TTL）后再点播放 → 应自动重拉一次 `GET /videos/{id}` 刷新 URL，不死循环。

### Phase 5 — 常见坑 / 排错
| 现象 | 原因 / 处理 |
|---|---|
| 文生/图生报 `ModelNotOpen` | Ark 控制台没开通 Seedance 模型 → 去开通 |
| 播放/下载 404、主机名解析失败 | `ENGINE_S3_PUBLIC_ENDPOINT` 填成了 `minio:9000` → 改 `http://localhost:9000` |
| 端口起不来 | 8000/3000 被 winnat/node 占 → 后端用 8080；`taskkill` 清 3000 |
| 仍出现 `file://` 链接 | 没读到新后端镜像 → `--build` 重建 |
| 下载/跨域失败 | MinIO bucket 配 CORS allow `http://localhost:3000` |
| 任务"完成→排队中"回退 | 不应发生（双映射已修）；若出现，抓 `GET /videos/{id}` 响应核对 status/字段 |
