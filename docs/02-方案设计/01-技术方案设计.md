# 华鼎 AI 短视频引擎 · 技术方案设计

> 版本 v0.1｜日期 2026-06-05｜负责人：Cowork｜对应 SOP 第 2 步（Superpowers · 方案设计）
> 输入依据：01-项目规划 全套文件 + 需求澄清结论。本文件描述"怎么建"，implementation plan 描述"分几步建"。

---

## 1. 设计目标与原则

1. **复用优先**：最大化复用 Pixelle-Video 的引擎资产（pipelines + api_services + prompts + 模板），不重造生成内核。
2. **中台思维**：在生成内核之上，构建多租户、批量、协作、计费、分发的企业中台。
3. **解耦分层**：前端 / API / 业务服务 / 生成引擎 / 能力抽象 / 基础设施，层层解耦，便于多 Agent 并行开发。
4. **异步为本**：视频生成是长耗时任务，全链路异步化、可水平扩展。
5. **电商先行**：首行业电商带货，模板/话术/商品流水线优先打磨。

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Next.js + TypeScript + Tailwind + shadcn/ui | B 端控制台标准；SSR；组件生态成熟 |
| 状态/请求 | React Query + Zustand | 服务端状态缓存 + 轻量本地状态 |
| 后端 | Python 3.11 + FastAPI | 直接复用原引擎，最小化重写 |
| 任务队列 | Celery + Redis | 长耗时生成任务异步化、可扩展 |
| 数据库 | PostgreSQL | 多租户 + 关系 + JSON 字段 |
| 缓存 | Redis | 会话、队列、限流 |
| 对象存储 | 阿里 OSS（S3 兼容） | 素材、成片、模板 |
| 实时 | WebSocket / SSE | 进度推送（复用原 progress 模型） |
| 鉴权 | JWT + RBAC | 多租户与角色权限 |
| 部署 | Docker + K8s | GPU 节点弹性伸缩；仅 SaaS |
| 监控 | Prometheus + Grafana / 日志平台 | 性能与错误（配合 Chrome DevTools 验证） |

## 4. 生成引擎蒸馏方案

### 4.1 复用与改造
- **保留**：`pipelines/`（四套编排）、`api_services/`（供应商抽象）、`prompts/`、`templates/`、`frame_processor`（封面）、`history_manager`、`progress` 模型。
- **改造**：把引擎从"单机直跑"改为"被业务层以任务方式调用"——每个生成请求封装为 Celery 任务，进度写回 Redis/DB，产物落 OSS。
- **剥离**：去掉 Streamlit UI 层；配置从单机 YAML 改为"租户级配置 + 平台级密钥托管"。

### 4.2 华鼎新增 pipeline
- **ecommerce（电商带货）**：输入商品（标题/卖点/主图）→ 生成卖点脚本 → 商品图融合配图 → 口播/字幕 → 套电商模板 → 成片。首行业重点。
- **digital_human（数字人矩阵）**：企业数字人 + 音色，文案批量驱动口播，供多账号分发（P1）。

### 4.3 能力层接入（已有 Key）
LLM（通义/DeepSeek/GPT）、图像（DashScope/Seedream/GPT）、视频（DashScope/Kling/Seedance）、TTS（edge-tts/index-tts）、VLM（反推）。平台侧统一托管密钥，按租户路由与计量。

## 5. 多租户与权限

- **隔离**：共享库 + `tenant_id` 行级隔离（起步）；敏感大客户后续可升级 schema 隔离。
- **模型**：Tenant（企业）→ Org/Team（团队）→ User（成员）→ Role（角色）。
- **角色**：管理员 / 运营 / 创作者 / 审核员 / 开发者（API），对应 RBAC 权限矩阵。
- **配额**：每租户并发任务数、月度生成额度、存储上限按套餐配置。

## 7. API 设计（在原 api/routers 基础上扩展）

- **复用/改造**：content、image、video、tts、llm、frame、tasks、files、resources。
- **新增**：auth（登录/租户）、tenants、users/roles、brands、templates、batches、approvals、publish、accounts、analytics、billing、webhooks。
- **风格**：REST + OpenAPI 自动文档；长任务返回 task_id + WebSocket 订阅进度；对外开放 API 走独立鉴权与配额。

---

## 8. 计费（套餐制）

- **套餐分档**：如 基础 / 专业 / 旗舰，差异在月度生成额度、并发数、席位数、可用模型、存储、是否开放 API。
- **计量**：每次生成写 usage_record（模型/token/算力时长/估算成本），用于额度扣减与成本核算。
- **超额**：本期采用"额度用尽即限制/提示升级"（暂不做按量叠加，保持套餐简单）。

---

## 9. 发布中心（分发平台）

- **接入顺序**：抖音 → 小红书 → 视频号 → B 站（优先官方开放平台 API）。
- **能力**：账号矩阵管理（多账号授权）、定时发布、频控与合规、发布回执与失败重试。
- **数据回流**：拉取各账号发布后的播放/互动数据，进数据看板。

---

## 10. 安全与合规

- 密钥服务端托管，不下发前端；素材/成片 OSS 私有读写 + 临时签名 URL。
- JWT + RBAC，租户数据严格隔离。
- 保留 Pixelle-Video 的 LICENSE/NOTICE 与版权声明；关于页注明二次开发。
- 发布遵守各平台风控与频控；内容生成保留人工审核环节。

---

## 11. 关键技术风险与对策

| 风险 | 对策 |
|---|---|
| 引擎从单机改任务化的改造量 | M1 先做最小改造跑通，再逐步异步化/多租户化 |
| 多模型 API 稳定性与成本 | 能力层做超时/重试/降级；按租户计量控成本 |
| 长任务并发与 GPU 调度 | Celery 分队列 + GPU 节点弹性；优先用直连 API 降低自有算力压力 |
| 发布平台接口风控 | 走官方开放平台；账号矩阵做频控；失败重试与人工兜底 |
| 前端重写工期 | 后端最大化复用，前端按 P0 控制台核心流程先行 |
