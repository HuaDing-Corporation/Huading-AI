> 适用范围：定价、钱包、品牌音色、供应商配置、豆包官方音色注册及相关前后端发布

## 3. 两阶段生产门禁

以下所有就绪命令都必须使用无应用依赖的运维包装器。该包装器将 stdout 严格保留为
一份脱敏 JSON 文档；配置、导入、运行时或输出校验失败只返回通用 JSON，且不回放
捕获的 stderr。生产 Compose 与环境样例中的自动迁移默认关闭，routine 与 staged
启动都必须保持关闭。后续启动 worker 与 nginx 时必须带 `--no-deps`，防止 Compose
重新评估或重建已经过审计启动的 backend。

### 3.1 阶段一：旧库迁移前 `preflight`

生产为 `20260724_0031` 时，唯一允许的发布就绪入口是新发布镜像中的
`preflight`。它只读取旧表与 Alembic revision，不查询 `0036`–`0038` 新表：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python scripts/ops/pricing_closure_readiness_cli.py preflight
```

只有 exit `0`、`ready: true`、`migration_revision: 20260724_0031` 才允许进入
迁移。此时直接运行完整 `audit` 应安全返回 `SCHEMA_NOT_READY`；不能把它的
exit 2 误当成业务 blocker，也不能跳过 `preflight`。

`preflight` 必须同时证明：生产环境标识正确、签署的官方精确清单非空且
覆盖历史音色、旧费率满足 0032/0035/0037 的 CAS 前置值、无租户覆盖或
重复/非法费率、usage 数值合法、迁移 seed ID 无冲突、钱包预留与历史
reserved usage 一致。

### 3.2 阶段二：迁移后、登记前的限定过渡态

迁移到 `20260829_0038` 后立即运行完整 `audit`。首次官方登记前它预期
exit `2`，但只有以下条件全部成立时才允许继续：

- blocker 恰好一项，code 为 `OFFICIAL_DOUBAO_REGISTRY_MISMATCH`；
- `inventory_unknown_count` 为 0；
- `provider_inventory_counts.active_official_registry_ids` 为 0；
- 不存在官方清单与 active/retired 客户 registry 的交集；
- 费率、账务、钱包、历史写入口和其他 registry 不变量均无 blocker。

这是唯一允许的非零 `audit` 过渡态。`register-official` 在数据库锁内重新
计算同一完整 readiness；任一额外 blocker 都会在写入前返回
`OFFICIAL_REGISTRATION_ABORTED`。

### 3.3 阶段三：登记后完整审计

`register-official` 成功后立即重跑 `audit`。只有 exit `0`、`ready: true`
且 blockers 为空，才允许进入 smoke、对账和 canary。命令输出只包含安全
的记录 ID、计数与费率证据，不展开官方或客户 provider ID；仍不得粘贴
密码、密钥、连接串或生产环境文件内容。

### 3.4 严格空库首次启动 `bootstrap-empty-preflight`

真正空库不得使用面向旧 `0031` 数据库的 `preflight`，也不得运行
`infra/deploy.sh`。首次启动必须固定干净 checkout 与获批 release SHA，只构建一次
全部应用镜像，并在同一获批窗口内按以下顺序执行：

1. 只启动 PostgreSQL、Redis 与 MinIO；保持 nginx、backend、frontend 和全部
   worker 停止。先执行与第 5 节相同的 `broker-only --wait-seconds 300
   --poll-seconds 10` 门禁，确认四个 broker 队列与 unacked 连续稳定为零，再创建、
   验证受限存放的 custom-format 空库基线备份。
2. 使用已构建的目标 backend 镜像运行严格空库门禁：

   ```bash
   sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
     run --rm --no-deps backend \
     python scripts/ops/pricing_closure_readiness_cli.py bootstrap-empty-preflight
   ```

   只有数据库完全无表、生产环境标识正确、官方精确清单存在且规范、获批默认
   价格一致、旧写入口已退役时，该命令才允许 exit `0`、`ready: true`。部分初始化
   或已存在任意表的数据库必须阻断，不能改用旧库 `preflight` 绕过。
3. 在所有应用写入者和公网入口仍停止时，用同一目标镜像执行
   `alembic upgrade head`，并用 `alembic current` 确认唯一目标 revision。

   ```bash
   sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
     run --rm --no-deps backend alembic upgrade head
   sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
     run --rm --no-deps backend alembic current
   ```

4. 按第 3.2、3.3 节及第 5 节后续顺序继续：只接受登记前限定过渡态，执行
   `register-official` 恰好一次，登记后及 backend 启动后两次完整 audit 均通过，
   再启动全部 worker；固定三 worker 的 release probe 通过后才可启动 nginx。
5. 空库首次启动不豁免 smoke、账务对账、canary、最终审批或工作台状态签署。

## 4. 一票否决条件

出现以下任一情况，执行人必须停止发布、保留现场并升级审批人：

- 旧库 `preflight` 非零退出，或生产数据库备份未验证可读取/恢复。
- 迁移后登记前的 `audit` 不满足第 3.2 节全部限定条件。
- 注册后 `audit` 非零退出，或出现任何 blocker/warning 被审批规则定义为阻断。
- 停止全部 worker 后的 `broker-only` 门禁非零退出，四个获批 broker 队列与 unacked 未连续稳定为零，或发现任何未批准非空逻辑队列。
- 生产 revision、ENV、费率、租户覆盖项与已审批内容不一致。
- Wallet、BrandVoice、ProviderConfig 或官方槽位快照不完整，或导出范围遗漏 inactive 数据。
- 平台负责人未签署准确官方 ID 清单，或执行时清单与签署版本不一致。
- 官方精确清单与任何 active/retired 客户 registry ID 相交。
- 历史记录的 `owner_user_id`、`activated_at`、`expires_at` 任一不再为 null。
- 后端、前端与迁移未在同一获批变更窗口内按本文件顺序共同发布，或被拆分成互不关联的发布。
- 客户豆包路由未保持 fail closed，或 registry/config/inventory 三者不一致。
- 注册命令已被执行过、执行次数无法证明，或输入不是获签的 `ENGINE_DOUBAO_OFFICIAL_VOICE_IDS`。
- 任一 smoke test、账务守恒、幂等、退款、恢复或对账检查失败。
- 有人提议用手工数据库编辑、临时脚本、跳过检查或重跑掩盖失败来解除阻断。
- 缺少独立、明确、可追溯的生产审批。

## 5. 生产执行顺序（不得调序或合并审批）

从最终备份开始，到登记后审计成功为止，必须是同一个**无业务写入静默窗口**。
旧 API、Celery worker 或公网入口只要还有一个可能写库，备份和 preflight 证据就
会变旧，不能授权迁移。首次定价闭环发布不得运行 `infra/deploy.sh`。

获批 SHA 固定后，先在旧服务仍在线时只构建全部应用镜像：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  build backend worker worker-image worker-video frontend
```

进入维护窗口时先关闭公网入口，再用 count-only 门禁等待在途任务进入可证明的
持久化终态。第一次连续归零后，以 1,800 秒宽限停止 backend，随后再次排空以
关闭最后的入队竞态；第二次连续归零后，才可以相同宽限停止全部 worker。
数据库、Redis 和 MinIO 始终保持运行：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  stop nginx
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python -m scripts.ops.celery_release_gate drain \
  --expected-workers 3 --wait-seconds 1800 --poll-seconds 10
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  stop -t 1800 backend
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python -m scripts.ops.celery_release_gate drain \
  --expected-workers 3 --wait-seconds 1800 --poll-seconds 10
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  stop -t 1800 worker worker-image worker-video
```

任一次 active、reserved、scheduled、逻辑队列或 unacked 计数未连续归零，都必须
停止发布并升级审批人；不得缩短宽限、直接杀死任务或只依赖 broker-only 继续。
全部 worker 停止后、重新启动 backend 前，再从 one-off 目标镜像执行 broker-only
边界门禁；该命令不会重启 backend 服务：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python -m scripts.ops.celery_release_gate broker-only \
  --wait-seconds 300 --poll-seconds 10
```

只有 `default`、`avatar`、`image`、`video` 四个获批 broker 逻辑队列、所有实际
发现的未批准逻辑队列与 unacked 在门禁连续采样中稳定为零，才可继续创建最终备份、
迁移或重启 backend。采集必须覆盖 Redis 全局 key prefix 与 Kombu priority key；
对外只输出安全合计数，不得输出队列名或任务名。命令失败时必须保持 nginx、backend
与全部 worker 停止并中止发布。

确认上述五个服务均保持停止后，创建**最终静默备份**：PostgreSQL custom-format、
`pg_restore --list` 可读且 SHA-256 已记录。更早的在线备份只能作辅助证据，不能
替代这一份回滚基线。随后在仍为 `0031` 的数据库上运行：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python scripts/ops/pricing_closure_readiness_cli.py preflight
```

只有 preflight exit 0 且取得独立执行确认，才允许在应用仍全部停止时显式迁移：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend alembic upgrade head
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend alembic current
```

迁移后先运行登记前完整审计：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python scripts/ops/pricing_closure_readiness_cli.py audit
```

只接受第 3.2 节的唯一过渡态。随后仅运行一次登记命令：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python scripts/ops/pricing_closure_readiness_cli.py register-official
```

登记后立即再次运行完整审计，命令不得用口头引用代替：

```bash
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  run --rm --no-deps backend \
  python scripts/ops/pricing_closure_readiness_cli.py audit
```

第二次审计 exit 0 后，必须设置 `BACKEND_AUTO_MIGRATE=0` 再启动 backend/frontend，
确保启动过程不能修改已审计的数据库，并从运行中的 backend 再审计一次；该审计也
通过后才启动 worker。固定三 worker 的 release probe 必须 exit 0、
`ready: true`，且三个 worker 的队列拓扑分别为 `{default, avatar}`、`{image}`、
`{video}`；随后才可最后打开公网入口：

```bash
sudo env BACKEND_AUTO_MIGRATE=0 \
  docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  up -d --no-build backend frontend
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  exec -T backend python scripts/ops/pricing_closure_readiness_cli.py audit
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  up -d --no-build --no-deps worker worker-image worker-video
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  exec -T backend \
  python -m scripts.ops.celery_release_gate workers \
  --expected-workers 3 --wait-seconds 300 --poll-seconds 10
sudo docker compose -f infra/docker-compose.prod.yml --env-file infra/.env \
  up -d --no-build --no-deps nginx
```

backend/frontend、任一 worker 或 nginx 的 Compose 启动、运行 revision 检查、启动后
audit、worker release probe 任一失败时，都必须继续执行统一 fail-closed 清理：显式停止
nginx、backend、frontend 与全部 worker；某个 stop 命令失败也不得跳过其余服务，并始终
保持公网入口关闭。两个早期 drain 门禁失败是唯一例外：不得启动目标版本，同时保留旧
worker 供受控恢复，不能因统一清理而提前杀死旧任务。

| 序号 | 必须动作 | 完成证据 | 未满足时 |
|---:|---|---|---|
| 1 | **只读确认**生产 checkout 干净、当前 SHA/revision、ENV、全部费率和租户覆盖项 | 带时间戳的只读快照与审批单关联 | 停止 |
| 2 | 导出 Wallet、BrandVoice、全部 active/inactive ProviderConfig、官方槽位快照 | 四类完整导出文件及行数/校验摘要 | 停止 |
| 3 | 平台负责人签署准确官方 ID 清单；真实清单仅写入受信任的 `infra/.env` | 安全审批附件引用与签名；仓库样例保持空值 | 停止 |
| 4 | 固定获批 release SHA，只构建 backend/全部 worker/frontend 镜像，不重启旧容器 | HEAD、全部镜像摘要与获批 SHA 一致 | 停止 |
| 5 | 关闭 nginx，排空在途工作，停止 backend 与全部 worker，再运行 `broker-only` | 四个获批 broker 队列、所有未批准逻辑队列与 unacked 连续稳定为零；五个服务均停止 | 保持 nginx/backend/workers 停止 |
| 6 | 在无写入者状态创建最终 PostgreSQL custom-format 备份，验证 `pg_restore --list` 并记录 SHA-256 | 最终备份路径、大小、校验和、验证时间 | 停止 |
| 7 | 在仍为 `0031` 的生产库运行新镜像 `preflight` | exit 0、`ready: true`、无 blocker | 保持所有写入者停止 |
| 8 | 取得一次**独立、明确的生产执行确认** | 审批人、时间、范围、release SHA 和最终备份引用齐全 | 停止 |
| 9 | 用 one-off backend 显式迁移，应用服务仍保持停止 | Alembic 到达 `20260829_0038` | 停止并按发布预案处置 |
| 10 | 验证历史新增归属/期限字段仍为 null | revision 与零异常只读摘要 | 停止 |
| 11 | 运行登记前完整 `audit`，只接受第 3.2 节限定过渡态 | 唯一 mismatch blocker、unknown=0、active official=0 | 停止 |
| 12 | 仅使用已签署清单执行 `register-official` **恰好一次** | exit 0、登记数量、审批引用；输出不含 provider ID | 停止；不得自行重跑或手工补写 |

重启 backend/frontend 前，`infra/deploy.sh` 必须执行上面的 `broker-only` 命令，
证明四个获批队列、任何未批准非空逻辑队列与 unacked 均连续稳定为零；随后在所有
应用写入者仍停止时，从目标镜像 one-off 完整 `audit`。只有该审计 exit 0 才可启动
backend/frontend；启动后还要重新验证 revision 并再次完整 audit。上述启动、检查、

## 6. 业务闭环验收

生产 smoke 必须覆盖完整资金生命周期，不得只验证页面成功提示：

1. `estimate` 只读且返回权威报价；报价失败时前端保持关闭，不能继续提交。
2. `reserve` 成功后才允许调用供应商；提交同时具备报价与幂等计费头。
3. 成功路径完成 `settle`，未使用额度完成 `release`。
4. 人工品牌音色订单分别验证 fulfill 与 reject；退款只发生一次。
5. 相同幂等键重复请求不重复扣款、不重复注册、不重复交付。
6. 未知网络结果通过权威查询恢复，不向客户声称未经确认的释放或成功。
7. 每个终态均满足 `requested = settled + released` 且 `held_credits = 0`。
8. 最终对账 Wallet、UsageRecord、供应商成本和业务产物；任一差异均阻断上线。
