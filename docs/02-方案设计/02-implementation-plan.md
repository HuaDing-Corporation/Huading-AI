## M1 · 引擎蒸馏 + 后端骨架

**目标**：让生成内核以"任务"方式被 API 调用，跑通最小闭环。

工作分解：
1. Fork/导入 Pixelle-Video，剥离 Streamlit，保留 pipelines/api_services/prompts/templates。
2. FastAPI 后端骨架：项目结构、配置、依赖注入、OpenAPI。
3. 接入已有模型 Key，能力层联调（LLM/图像/视频/TTS 各通 1 条）。
4. 引擎任务化：单次生成封装为 Celery 任务；进度写 Redis；产物落 OSS。
5. 最小 API：提交主题 → 返回 task_id → WebSocket 订阅进度 → 取成片 URL。
6. 单租户跑通（多租户留到 M2）。

**里程碑**：`POST /generate` 异步产出一条视频成功，附进度与产物。
**主力 Agent**：Claude Code（引擎改造）、Codex A（后端骨架）。

---

## M2 · 企业底座 + 控制台 MVP

**目标**：从"能生成"到"企业能用"。

后端：
1. 多租户 + 组织/团队 + RBAC（管理员/运营/创作者/审核员）。
2. 鉴权（JWT），租户级配置与配额。
3. 数据模型落地（tenant/user/project/video_task/brand_asset/template）。
4. 品牌资产库基础版（Logo/配色/片头尾/水印）。
5. 电商 pipeline 第一版（商品→脚本→配图→口播→模板→成片）。

前端（先做 SOP-4 设计系统，再 SOP-5 实现）：
6. UI/UX 设计系统（UI UX Pro Max）：视觉方向、配色、字体、组件规范。
7. 控制台 MVP：登录/工作台/单条生成/任务列表/素材与历史/品牌库。

**里程碑**：企业用户登录 → 配置品牌 → 用电商 pipeline 生成 → 下载成片。
**主力 Agent**：Codex A（前后端）、Claude Code（多租户/复杂逻辑）、Codex B（测试）。

---

## M3 · 差异化能力

**目标**：补齐企业中台的批量与协作壁垒。

1. 批量生产中心：上传商品表/选题表 → 批量子任务 → 队列管理 → 批量导出。
2. 团队协作 + 审批流：项目/文件夹、生成→审核→发布状态机。
3. 模板中心 + 封面中心：模板浏览/自建、批量封面、品牌水印统一注入。
4. 数字人口播 / 声音克隆 / 多语种 TTS。
5. 自定义素材分析生成脚本（VLM 反推）。

**里程碑**：可批量、协作化、品牌一致地生产电商视频。
**主力 Agent**：Codex A（前后端）、Claude Code（批量编排/状态机）、Codex B（回归）。

---

## M4 · 分发 + 计费 + 数据

**目标**：打通"生产→分发→数据"闭环，形成商用版。

1. 发布中心：抖音 → 小红书 → 视频号 → B 站（按序接官方 API）。
2. 账号矩阵：多账号授权、定时发布、频控合规、失败重试。
3. 套餐计费：套餐分档、usage_record 计量、额度扣减与升级提示。
4. 数据看板：生产量/成本/发布效果回流分析。
5. 开放 API / Webhook：供企业系统集成（电商后台触发生成）。

**里程碑**：电商客户可在平台内完成 生产→多平台分发→数据回看，并按套餐计费。
**主力 Agent**：Codex A、Claude Code、Codex B。

## 贯穿全程的工程纪律（SOP 6–12）

- 每功能完成 → **Code Simplifier** 整理代码（功能不变）。
- **Webapp Testing/Playwright** 自动测（页面/按钮/表单/筛选/跳转/移动端）。
- **Chrome DevTools** 查 Console/Network/接口/性能。
- 合并前 **Code Review**；出 bug/测试失败 → **Ralph Loop** 循环修复至通过。
- 每阶段末 **Claude-mem + Planning-with-files** 记录进度/决策/下一步（Hermes 负责）。
- **GitHub/gh CLI** 管分支/Issue/PR。
