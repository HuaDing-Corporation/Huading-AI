## 【任务包 #001】仓库初始化与项目脚手架
- 指派给：Codex A（后端）
- 阶段：M1 / BE-1
- 目标：在已有 GitHub 仓库中建立华鼎项目骨架与协作规范，作为全项目地基。
- 背景：项目为前后端分离——后端 Python 3.11 + FastAPI，前端 Next.js + TS。**采用 monorepo**（用户已定）。本地仓库已 `git init` 并完成 initial commit（含规划文档）；主分支已重命名为 `main`。用户已用 git worktree 给 Codex A/B 各开独立工作目录，Codex A 在 `feature/codex-a` 分支的 worktree 中作业。
- 要求：
  1. **关联远程并推送**：`git remote add origin <华鼎 GitHub 仓库地址>`，把 `main` 与 `feature/codex-a` 推到远程（`git push -u origin main` 等）；确认远程可见。（远程地址向用户索取。）
  2. 初始化 **monorepo** 结构（backend / frontend / docs / infra 顶层目录），含根 README、.gitignore、LICENSE、保留 Pixelle-Video 的 NOTICE；建议用 workspace（如 pnpm workspace + uv/poetry）统一管理。**保留已有规划文档目录（01-/02-/03-），勿删。**
  3. 分支策略：main（保护）/ develop / feature/* / fix/*，配 PR 模板与 Issue 模板。
  4. 添加 `.gitattributes` 统一换行符（消除 LF/CRLF 警告）。
  5. 后端：pyproject + 依赖（fastapi/uvicorn/celery/redis/sqlalchemy/pydantic 等）+ 基础目录。
  6. 前端：Next.js + TS + Tailwind + shadcn/ui 脚手架。
  7. CI 基础：lint + 测试占位（GitHub Actions）。
- 用到的 Skill：GitHub / gh CLI
- 交付物：已关联远程、可克隆运行的空骨架 monorepo + 分支与模板 + README 说明。
- 验收标准：远程仓库可见 main 与 feature/codex-a；本地能装依赖、分别起前后端空服务、CI 跑通；换行符警告消失。
- 依赖：GitHub 远程仓库地址（向用户索取）。
