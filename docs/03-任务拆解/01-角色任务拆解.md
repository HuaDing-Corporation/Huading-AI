# 角色任务拆解（Gstack WBS）

> 版本 v0.1｜日期 2026-06-05｜对应 SOP 第 3 步（Gstack）
> 输入：02-方案设计（技术方案 + implementation plan）。把工作按角色拆解，映射到执行 Agent。
> 派发走人工传达：Cowork 出【任务包】→ 用户转 Agent → Agent 回执 → 用户转回 Cowork。

## 1. 角色 → Agent 映射

| 虚拟角色 | 主责 Agent | 职责范围 |
|---|---|---|
| 产品（PM） | Codex A | 需求细化、PRD、任务拆解、验收标准 |
| 前端（FE） | Codex A（+ Frontend-design / UI UX Pro Max） | 控制台页面与组件 |
| 后端（BE） | Codex A | API、业务服务、数据模型 |
| 引擎（Engine） | Claude Code | 蒸馏改造、任务化、复杂逻辑、疑难 bug |
| 测试（QA） | Codex B（Webapp Testing/Playwright + Chrome DevTools） | 功能/回归/浏览器/性能测试 |
| 审查（Review） | Codex B（Code Review） | 合并前代码审查 |
| 修复（Fix-loop） | Claude Code / Codex B（Ralph Loop） | bug/测试失败循环修复 |
| 记忆（Memory） | Hermes（Claude-mem + Planning-with-files） | 进度/决策记录、复盘、skills 沉淀 |

> 横切纪律：每功能后 Code Simplifier（整理代码）；GitHub/gh CLI 管分支/Issue/PR。

## 6. 派发策略

- **首批只派 M0 收尾 + M1 地基**（详见 02-首批任务包.md），因为后续任务都依赖仓库与引擎骨架。
- 每完成一批回执后，Cowork 汇总、决策，再派下一批，避免一次性铺开导致依赖错乱。
- 阻塞项（法务确认）未清前，引擎导入可先在内部分支进行，但商用发布前必须完成合规。
