# 华鼎项目 — 迁移到 Mac 指南（含 codex-a / codex-b 迁移）

> 核心原则：**git worktree 不能直接拷贝**（里面是绝对路径 + 指向主仓 .git 的链接，跨机/跨系统必坏）。
> 正确做法 = 在 Mac 上**重新 clone + 重新 `git worktree add`**。真正的代码都在 GitHub `develop` 上，本地 worktree 只是工作副本。
> 芯片：**Apple M3 (arm64)**；Claude/Codex 已登录同账号 → **跳过登录步骤**。

---

## ★ 最省事：一键脚本 `mac_setup.command`

把 workspace 里的 **`mac_setup.command`** 传到 Mac，它会自动做：装 Homebrew/node/git/gh/Docker、确保 Claude/Codex（已登录免重登）、配 git 代理、clone 仓库、`checkout develop`、**重建 codex-a / claude-code / codex-b 三个 worktree**、还原 `infra/.env`、生成两台机同步助手脚本。

**怎么把脚本弄到 Mac（任选一）**：
- 上传到 **飞书云盘**，Mac 上从飞书下载到 `~/下载/`；或
- 微信/邮件发给自己；或 AirDrop。

**在 Mac 上跑**：
```bash
chmod +x ~/Downloads/mac_setup.command   # 路径按你实际放的位置
~/Downloads/mac_setup.command            # 或直接双击；首次双击若被拦：右键→打开
```
脚本跑完只剩 **3 件手动事**：①打开 Docker Desktop 一次；②Claude Code 里装 14 个 skill（见《Skills安装与使用流程》）；③填 `infra/.env` 的 3 个 key（JWT / DeepSeek / Seedance）——**或**把 Windows 的 `infra/.env` 改名 `huading-infra.env` 放到 Mac 的 `~/Downloads/`，脚本会自动连 key 一起还原，连填都免了。

> M3 专属：pg/redis/minio/node/python 都有 arm64 原生镜像，直接 `docker compose ... up --build` 即可，无需 `--platform`；个别只有 amd64 的镜像会被 Rosetta 模拟（慢一点，不影响功能）。

---

## ★★ 两台设备进度同步（你的唯一硬要求）

**同步主干 = Git + GitHub。** 只要养成"坐下先拉、离开前推"，两台机进度就一致：

| 时机 | 操作 | 用脚本 |
|---|---|---|
| 坐到任一台机开工前 | 拉最新 | 双击 `~/Projects/华鼎-拉取最新.command`（Win 上用 git pull） |
| 离开前 | 提交+推送当前分支 | 双击 `~/Projects/华鼎-提交并推送.command` |

要同步的东西分三类：
1. **代码 + 计划/进度**（在 git 里）：push/pull 自动同步。Planning-with-files 把进度写成 repo 里的 markdown、GitHub 的 Issue/PR 也是共享的 → 天然两机一致。**所以关键就是勤 push/pull。**
2. **项目文档**（我做的任务包/回执/指南，现在在桌面 `华鼎AI全自动短视频引擎` 文件夹，**不在 git**）：传到 **飞书云盘 / 云文档**，两台机随时看（手机也行）。**最彻底**则是 commit 进仓库的 `/docs`，走 git 自动同步、连飞书都不用。
3. **密钥 `infra/.env`**：很少变。放一份到 **飞书云盘**（私有）；换机时下载到 `~/下载/huading-infra.env`，`mac_setup.command` 自动还原（含 key）。

> 飞书 vs OneDrive 的区别：飞书是**上传/下载 + 在线文档**，不是 OneDrive 那种"本地文件夹后台自动同步"。对文档无所谓（甚至更方便）；对 `.env` 就是换机下载一次（它本来就很少变）。**代码/进度走 Git，与用哪个网盘无关。**

不会自动同步的：Claude-mem 的本地记忆、Cowork 这台机的项目 memory —— 但**真正的共享进度记录在 git + 上面的文档**里，所以不影响你两机接续。

## 阶段 0 · 离开 Windows 前，先保住"不在 Git 里"的东西

这些不在仓库里，重 clone 拿不回来，必须手动备份/记下来：

1. **每个 worktree 里的未提交改动**：在 `codex-a`、`codex-b`、`claude-code` 各跑 `git status`；有改动就 `git add -A && git commit && git push`（推到对应分支）。已合并的 #15/#17/#18 在 GitHub 上，安全。
2. **`infra/.env`**（被 gitignore，含密钥）：复制出来。里面有 `JWT_SECRET_KEY`、DeepSeek key（`ENGINE_LLM_API_KEY`）、Seedance/方舟 key（`ENGINE_SEEDANCE_*`）、MinIO 配置（`ENGINE_S3_*` / `MINIO_ROOT_*`）。
3. **skills 文档文件夹**（`桌面\skills\claude code skills\`）和 **项目资料文件夹**（华鼎AI… docs）——单独拷贝，它们不在 git 仓里。
4. **不要拷**：`node_modules`、Docker 卷、`.git/worktrees`、各 worktree 文件夹本身。Mac 上重建（尤其 Apple Silicon 架构不同）。

## 阶段 1 · Mac 装基础工具

```bash
# 1) Xcode 命令行工具（带 git）
xcode-select --install

# 2) Homebrew（包管理器）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 3) Node 22+ 和 Python（Codex CLI 要 Node 22+）
brew install node python git

# 4) Docker Desktop for Mac（按芯片选 Apple Silicon / Intel 版）
brew install --cask docker
# 装完打开 Docker Desktop 一次，等它就绪

# 5) Claude Code（官方原生安装器，推荐）
curl -fsSL https://claude.ai/install.sh | bash
# 备选：brew install --cask claude-code  或  npm install -g @anthropic-ai/claude-code

# 6) Codex CLI（注意是 @openai/codex）
npm install -g @openai/codex
# 备选：brew install --cask codex  或  curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

**代理（GitHub 在国内要）**：Bitz Net 是 Windows 的，Mac 换 **ClashX / Clash Verge / V2RayU**（同一份订阅）。装好记下本地 http 端口（Clash 默认 **7890**，和 Windows 的 7897 不同）。

## 阶段 2 · 配 git 代理 + 登录

```bash
# 走代理（端口按你 Mac 上代理软件实际端口，Clash 一般 7890）
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# GitHub 登录（二选一）
gh auth login                 # 用 GitHub CLI：brew install gh 后登录
# 或配 SSH key 后用 git@github.com:... 克隆
```

## 阶段 3 · clone 仓库 + 重建 worktree（codex-a / codex-b / claude-code）

```bash
# 1) 克隆到比如 ~/Projects
cd ~/Projects
git clone https://github.com/HuaDing-Corporation/-AI-.git
cd -AI-
git fetch origin
git checkout develop          # 主克隆停在 develop（集成分支）

# 2) 建放 worktree 的目录
mkdir -p ../华鼎-worktrees

# 3) 重建三个 worktree（关键：develop 只能被一个 worktree 占用，主克隆已占）
#   codex-a：后端开发分支（Codex A 沙箱不能建分支 → 在这里预建好分支）
git worktree add -b feature/m2-auth-fix-be ../华鼎-worktrees/codex-a develop

#   claude-code：前端开发分支
git worktree add -b feature/m2-auth-fix-fe ../华鼎-worktrees/claude-code develop

#   codex-b：审查用，不固定分支 → 用游离 HEAD，审谁就 checkout 谁
git worktree add --detach ../华鼎-worktrees/codex-b develop
#   审查时：cd ../华鼎-worktrees/codex-b && git fetch origin && git checkout <要审的分支>

# 查看 worktree 列表确认
git worktree list
```

> 说明：旧 Windows 上的 `feature/console-polish` 等本地分支别迁——它们合并后远程已删，Mac 上按当前/新任务**新建分支**即可。worktree 的分支名按任务来，不必复刻旧状态。

**还原密钥**：把阶段 0 备份的 `infra/.env` 放回主克隆的 `infra/.env`（worktree 各自也需要时同理复制）。

## 阶段 4 · 在 Mac 的 Claude Code 里重装 14 个 skill/MCP

安装命令是跨平台的，照 `Skills安装与使用流程-整理-20260611.md` 逐条在 Claude Code 里跑（`/plugin install …@claude-plugins-official`、`/plugin marketplace add …`、`claude mcp add chrome-devtools …`）。Mac 特别注意：

- **claude-mem**：需 Bun + uv → `brew install oven-sh/bun/bun uv`，再 `npx claude-mem start`。
- **Open Notebook**：Docker 应用，`docker compose up -d`（Mac 上 Docker Desktop 即可）。
- **Planning-with-files** 手动拷贝走 macOS 版命令（`cp -r ~/.claude/plugins/cache/... ~/.claude/skills/`）。

## 阶段 5 · Mac 上起全栈跑 e2e

```bash
cd ~/Projects/-AI-            # 主克隆（或你要部署的 worktree）
docker compose -f infra/docker-compose.full.yml up --build
```

- **端口**：Mac 没有 winnat 占 8000 的问题，可直接用 8000；但保持 `BACKEND_PORT=8080` 也行，省得改前端。`ENGINE_S3_PUBLIC_ENDPOINT=http://localhost:9000` 不变。
- 前端 `localhost:3000`，MinIO 控制台 `localhost:9001`，后端文档 `localhost:8080/docs`。
- **Apple Silicon**：pg/redis/minio/node/python 镜像都有 arm64，正常；个别只有 amd64 的会被 Docker 模拟运行（慢一点，不影响功能）。

## 关键避坑清单
1. **别拷 worktree 文件夹**——重 clone + `git worktree add`。
2. **`infra/.env` 是 gitignore 的**——必须手动迁，否则后端没密钥起不来。
3. **代理端口变了**——Windows 7897 → Mac Clash 一般 7890，git 代理要改。
4. **Node 要 22+**（Codex CLI 要求）。
5. **Docker 卷/node_modules 不迁**——Mac 上重建。
6. **skills 在 Claude Code 里跑流程最顺**——Cowork 这边装不了插件。
